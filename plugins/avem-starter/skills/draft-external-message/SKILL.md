# Draft an external message

A message to someone outside the team shapes what they decide about us.
Most mistakes in such messages are sentences that should not be there, not
sentences that are missing. So think about the reader first, write second,
and leave the sending to the user.

## 1. Analysis block (show it before the draft)

```
Reader decides:  what exactly the reader will decide based on this message
Helps:           what moves that decision the way we want
Hurts:           what creates doubt, gives leverage, or invites questions
Left out:        what I removed and why
Sources:         which documents or threads I checked for this reader
Claims:          every statement about dates, responsibilities, prices or what
                 a third party will do, each with its source and status:
                 [checked today: how] or [from notes dated DD.MM., not rechecked]
```

## 2. Write the draft

- One purpose, one clear ask, one next step.
- Every claim that is not marked "checked today" is written as a question or
  with a softener ("as far as we know", "planned"), never as a fact.
- No promises about our own future actions in passing ("when I sign" becomes
  "if we go ahead"), unless the user decided them.
- With experts (lawyers, accountants, engineers): ask how they would handle
  it instead of telling them what to do.
- Every amount says whose money it is ("you pay", "we invoice").
- Remove every sentence for which the answer to "what happens if it is
  missing?" is "nothing".

## 3. Check before handing over

- Read the draft once as the reader. Which question will they ask back?
  Answer it in one sentence, or remove what provokes it.
- Names, dates, amounts and attachments match the sources.

## 4. Hand over

Show the analysis block and the draft. Say what the user should check before
sending. Do not send, schedule or queue the message: the user sends it.
